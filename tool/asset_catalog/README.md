# Securities catalog build pipeline

The Flutter app ships with a precomputed NDJSON bundle of every
"mainstream" listed security across A-share / HK / US / crypto, baked
at build time and loaded into a local FTS5 table on first launch.
This directory holds everything needed to regenerate that bundle.

The runtime side lives in
[`apps/mobile/lib/data/securities_catalog/`](../../apps/mobile/lib/data/securities_catalog/) —
this README is for the build pipeline only.

## Layout

```
tool/asset_catalog/
├── build.py            bake CSV sources → securities.v1.ndjson + checksum
├── classify.py         A-share code-prefix → asset-type rules
├── common.py           shared CSV writer + OpenCC traditional→simplified
├── diff_report.py      compare a fresh bake vs. the previous bundle
├── requirements.txt    pinned Python deps for full ingest
├── sources/
│   ├── cn_a.py         BaoStock + mootdx adapter (SH+SZ+BJ)
│   ├── hk_stock.py     HKEX official xlsx adapter
│   ├── us_stock.py     NASDAQ Trader + SEC adapter
│   ├── crypto.py       CoinGecko top-N adapter
│   └── *.csv           per-source CSV (regenerated by --full, hand-editable for stub mode)
└── tests/              fixture-based offline tests
```

## Modes

The orchestrator is `tool/build-asset-catalog.sh`.

| invocation | what it does | network? |
|---|---|---|
| `./tool/build-asset-catalog.sh` | bake the existing CSVs into NDJSON | no |
| `./tool/build-asset-catalog.sh --full` | fetch every upstream source, regenerate CSVs, bake | yes |
| `./tool/build-asset-catalog.sh --full --allow-degraded` | as above, but a single-source outage doesn't abort | yes |
| `./tool/build-asset-catalog.sh --full --sources cn_a,crypto` | only re-run a subset | yes |
| `./tool/build-asset-catalog.sh --full --skip-bake` | regenerate CSVs but don't bake | yes |

Environment knobs:

* `CATALOG_VERSION` — override the version label (defaults to `v1.<UTC YYYYMMDD>`)
* `CATALOG_DIFF_THRESHOLD` — fraction at which the diff report turns into a warning (default `0.05`, i.e. 5%)
* `COINGECKO_API_KEY` — switch to the Pro endpoint and bypass the public rate limit

## Sources

| source | feed | license |
|---|---|---|
| A-share (SH+SZ) | [BaoStock](http://baostock.com/) HTTP API, queries `query_all_stock` + `query_stock_basic` | MIT (client) |
| A-share (BJ) + fallback | [mootdx](https://github.com/bopo/mootdx) (pytdx wrapper, TCP) | MIT |
| Hong Kong | [HKEX `ListOfSecurities.xlsx`](https://www.hkex.com.hk/eng/services/trading/securities/securitieslists/ListOfSecurities.xlsx) | publicly redistributable |
| US (NASDAQ + NYSE) | [NASDAQ Trader symbol directory](https://www.nasdaqtrader.com/dynamic/symdir/) | publicly redistributable |
| US (name enrichment) | [SEC `company_tickers_exchange.json`](https://www.sec.gov/files/company_tickers_exchange.json) | public domain |
| Crypto | [CoinGecko `/coins/markets`](https://www.coingecko.com/en/api/documentation) | free tier (10–30 req/min) |

### Runner constraints

BaoStock and mootdx are **mainland-China services** and can be less reliable
from GitHub-hosted runners in the US/EU. The automated refresh workflow still
uses `ubuntu-latest`, but runs the full ingest fail-closed: it never passes
`--allow-degraded`, so an unreachable source fails the run instead of
publishing a partial catalog. The workflow can be retried manually after a
transient outage. HKEX, NASDAQ Trader, SEC and CoinGecko are globally
reachable.

When BaoStock fails, the cn_a adapter automatically falls back to a
mootdx-only pass. The build script also runs an opt-in cross-check pass
(BaoStock vs. mootdx) and warns if the SH+SZ universes disagree by more
than 1% — this catches BaoStock data lag and mootdx protocol drift.

## Release integration

Releases package the committed catalog without fetching mutable upstream data.
Refresh the desired sources, run the offline tests and stub bake, then commit
the CSVs and generated NDJSON before creating a release tag.

The release workflow runs the following gate before Flutter setup:

```bash
python3 -m tool.asset_catalog.validate_release
```

It verifies the NDJSON count, canonical order, uniqueness and checksum; rejects
catalogs older than 45 days; and requires conservative minimum populations for
every production market. The current release floors are:

| Market | Minimum rows |
|---|---:|
| A-share | 4,000 |
| Hong Kong | 1,500 |
| US | 5,000 |
| Crypto | 400 |

After building, the same command compares the committed file byte-for-byte
with the copy in the APK, AAB, and Flutter web output. A release therefore
fails both when a full refresh was forgotten and when Flutter stopped packaging
the declared asset.

Catalog refresh remains separate from release creation so rebuilding the same
tag is deterministic and upstream outages cannot mutate or partially degrade a
published catalog.

`.github/workflows/securities-catalog-refresh.yml` runs every Monday at 02:00
Asia/Shanghai on a GitHub-hosted `ubuntu-latest` runner and also supports manual
dispatch. It performs a full refresh, runs the catalog test suite and release
validator, uploads the generated files for diagnostics, and creates or updates
the `automation/securities-catalog-refresh` PR when data changed. The PR is
never auto-merged.

The workflow uses `CATALOG_PR_TOKEN` when configured and otherwise falls back
to `github.token`. Repository settings must allow GitHub Actions to create pull
requests. Use a fine-grained PAT or GitHub App token for `CATALOG_PR_TOKEN` when
the created PR must trigger other workflows; events created by the default
`GITHUB_TOKEN` do not start new workflow runs.

## Output

`apps/mobile/assets/catalog/securities.v1.ndjson` — JSON header line
followed by one entry per line. The header carries `version` and a
deterministic FNV-1a 64 checksum that the loader compares to the local
`securities_catalog_meta` row. Bumping the source CSVs flips the
checksum, which triggers an atomic FTS5 re-population on next app
launch.

The bake step enforces a **gzip-compressed budget of 800KB** and aborts
if the new bundle is heavier.

## Testing

Each adapter has a fixture-based offline test that pins the parser
behaviour against captured upstream payloads. Run them with:

```bash
python3 -m pytest tool/asset_catalog/tests
```

The tests exercise pure parser functions and are run manually when catalog
sources or adapters change.

## Troubleshooting

* **`baostock login failed`** — BaoStock's public HTTP server is in CN.
  Either run from a CN host, or rerun with `--allow-degraded` (the
  fallback to mootdx will still try TCP, which has the same constraint
  but a different IP block).
* **`gzip-compressed catalog exceeds 800KB`** — usually the crypto
  top-N is too generous. Drop `--top-n` on `crypto.py` or trim the
  per-source `aliases` field.
* **`change ratio X% exceeds threshold 5%`** — the diff report tripped.
  Eyeball the report and either accept (raise `CATALOG_DIFF_THRESHOLD`
  for that run) or investigate the source feed for breakage.
